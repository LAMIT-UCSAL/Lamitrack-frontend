## Story

**Como** pessoa desenvolvedora das telas de Listagem (#4) e Detalhe (#5),
**quero** um card de evento que receba o evento exatamente como a API do backend o devolve,
**para que** as telas só precisem buscar os dados e passá-los ao card, sem adaptar campo por campo.

## Acceptance Criteria

1. **Tipo `Evento` igual ao contrato da API.** `app/lib/evento.ts` exporta o tipo `Evento` com os campos de `EventResponse` do backend (`id`, `title`, `description`, `startsAt`, `venue`, `city`, `uf`, `latitude`, `longitude`, `registrationUrl`, `source`, `bannerUrl`, `tags`), com `| null` nos campos que podem ser nulos na tabela. [Fonte: `Lamitrack-backend` `api/EventResponse.java` e `V1__criar_tabela_events.sql`]
2. **O card recebe o evento inteiro:** `<EventCard evento={evento} />`, com props tipadas. [Fonte: issue #13, "props tipadas"]
3. **Categoria vinda das tags.** A meta mostra a primeira tag que for uma das 5 categorias válidas. Se nenhuma tag for categoria, a meta mostra só a data.
4. **Data a partir de `startsAt`.** `startsAt` (data e hora locais, sem fuso, ex.: `2026-11-14T19:00:00`) vira "14 nov" na meta e `dateTime` no `<time>`, com o **mesmo resultado no servidor e no navegador** (sem deslocamento de fuso).
5. **Local legível:** `venue` e `city/UF` quando existirem (ex.: "Minex Hub · Salvador/BA"); a linha some se não houver nenhum dos três.
6. **Imagem:** `bannerUrl` quando existir; senão, o espaço reservado decorativo atual.
7. **Link interno para o detalhe:** o título leva a `/eventos/{id}` com o `Link` do React Router (navegação no cliente), mantendo o card inteiro clicável. [Fonte: issue #13, "pronto pra ser usado nas telas de Listagem e Detalhe"]
8. **Sem preço.** A API não tem preço; o card deixa de ter `price` e o selo "Gratuito". O rodapé mostra a cidade/UF em `cobalt` 800 (dado principal) e "Ver evento →". O token `--color-success` continua disponível para quando houver preço.
9. **A home provisória** usa um `Evento` de exemplo no formato da API; testes atualizados (envolvendo em roteador onde houver `Link`).
10. **Gates do CI passam:** `lint`, `format:check`, `typecheck`, `test`, `build`.

## Riscos

- **Fuso:** `new Date("2026-11-14T19:00:00")` é interpretado no fuso da máquina; no servidor (UTC) e no navegador (UTC−3) a data pode mudar perto da meia-noite e causar erro de hidratação. Formatar a partir dos componentes da string, sem `Date` local.
- **Tags livres:** o backend aceita qualquer tag (ex.: "gastronomia"); a comparação com as categorias deve ser exata e não deve quebrar com tags desconhecidas.
- **Rota inexistente:** `/eventos/:id` ainda não existe (#5); o link leva à 404 até lá.

## Dev Notes

**Contrato da API (verificado em 2026-11-03):** `GET /eventos` devolve `Page<EventResponse>` (Spring Data); `GET /eventos/{id}` devolve `EventResponse`:
`id: Long`, `title: String` (obrigatório), `description: String?`, `startsAt: LocalDateTime` (obrigatório; JSON ISO sem fuso), `venue/city/uf: String?`, `latitude/longitude: Double?`, `registrationUrl: String?`, `source: String` (obrigatório), `bannerUrl: String?`, `tags: Set<String>` (nunca nulo, pode ser vazio).

**Meses em pt-BR (abreviados, minúsculos, sem ponto):** jan, fev, mar, abr, mai, jun, jul, ago, set, out, nov, dez. Formatar pelos componentes `AAAA-MM-DD` da string, sem `new Date` (ver Riscos).

**Estado atual:** `EventCard` recebe props soltas (`title`, `category`, `date`, `dateTime`, `location`, `href`, `price`, `imageSrc`); usado só na home provisória e no próprio teste.
