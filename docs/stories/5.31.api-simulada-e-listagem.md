## Story

**Como** pessoa que procura eventos de inovação,
**quero** uma página com todos os eventos e filtros por categoria, cidade e data,
**para que** eu encontre o que me interessa. Enquanto a API do backend não está no ar, a página funciona com dados simulados no mesmo formato.

## Acceptance Criteria

1. **Cliente da API só no servidor** (`app/lib/api.server.ts`): `listarEventos(filtros)` e `buscarEvento(id)`. Com `LAMITRACK_API_URL` definida, chama `GET {url}/eventos` e `GET {url}/eventos/{id}` do backend; sem ela, usa os dados simulados. [Fonte: `Lamitrack-backend` `EventController`]
2. **Simulação fiel ao backend:** mesma resposta paginada do Spring (`content`, `totalElements`, `totalPages`, `size`, `number`, `first`, `last`, `numberOfElements`, `empty`); mesmos filtros (`city`, `uf` e `tag` por igualdade exata; `date` pelo dia de `startsAt`); `page`/`size` (padrão 0/20); `sort=startsAt,asc`. [Fonte: `EventFilter.java`, `EventListControllerIntegrationTest`]
3. **Dados simulados dentro dos critérios do catálogo** (`docs/fontes.md` do backend): só as 5 categorias, eventos futuros, Bahia presencial + online; editais com `startsAt` = prazo de inscrição.
4. **Rota `/eventos`:** kicker + título; filtro de categoria no trilho; filtros de cidade e data; grade de `EventCard`; ordem por data; paginação; tudo refletido na URL (dá para compartilhar o link filtrado). Os dados vêm de um `loader` (SSR).
5. **Lista vazia** com nota informativa e um jeito de limpar os filtros. [Fonte: issue #4]
6. **Editais:** a data aparece como "Inscrições até 14 nov" no card e no carrossel.
7. **Aviso de dados de exemplo** visível enquanto a API simulada estiver em uso.
8. **Home provisória** usa a mesma fonte (loader) em vez de eventos escritos na página.
9. **Navegação:** "Eventos" no header e no rodapé leva a `/eventos`.
10. **Configuração documentada:** `.env.example` e README explicam `LAMITRACK_API_URL`.
11. **Gates do CI passam.**

## Escopo

**Dentro:** cliente da API, dados simulados, `/eventos`, ajustes no card/carrossel/home/header/rodapé, testes.
**Fora:** tela de detalhe (#5; `buscarEvento` já fica pronto), busca por texto (o backend não tem), filtro "só futuros" no backend (anotado para o backend).

## Dependências

Contrato da API lido em 2026-11-03 na `main` do `Lamitrack-backend` (Spring Boot 3.5.15, `Page<EventResponse>` serializada direto).

## Riscos

- **Formato da página do Spring:** se o backend ativar `PageSerializationMode.VIA_DTO`, o formato muda para `{ content, page: {...} }`. O cliente fica isolado num arquivo só para ajustar fácil.
- **Datas da simulação:** ficam fixas; com o tempo passam a ser passadas. Aceitável para dados de exemplo.
